# Ver0.14.2 — 準備中でも操作を止めない読み込み

## 対応

- 入室時の全画面マスクと一括busyを廃止。背景と未使用の動作画像・隠れた物は入室条件に含めない。
- 見えている人物・家具・小物だけを先に準備。人物のポーズもフレーム単位の可逆WebPへ分割。
- 表示済み画像だけで透過クリック判定を行い、未読込の画像を待って他の物の操作を妨げない。
- 歩行と接触に使うフレームを使用直前に準備。読み込み済みのImageをクリック判定にも再利用。
- 失敗は8秒で打ち切り、他の物の操作を維持。画像の再試行ではアイテム・解決済み手順を保持。
- 動作途中のフレーム取得失敗は、実体の同一性を保って開始前へ戻し、busyを解除する。
- BGMの元バイナリ、元PNG、フレームの寸法・アルファ・見える画素は維持。

## 起動と障害の実ブラウザ検証

`tests/startup.cjs` は、背景・パパの初期画像・クリアポーズ・隠れたゲーム機の通信を意図的に止めたまま入室し、先に表示できた新聞を拾えることを確認します。途中でパパの画像だけを解放し、初期読み込み完了が実行中の動作のbusyを解除しないこと、その後に新聞がBAGへ入ることも確認。未使用画像が入室時に要求されないこと、全画面マスクがないことも検証します。

背景失敗後に新聞を取得してから画像だけを再試行し、所持品と手順が保持されることを確認。実際の接触に使うフレームを失敗させ、未解決・未取得の状態へ戻せること、再操作で取得できること、ゲーム機のオブジェクトが置き換わらないことも検証します。

起動時間はローカルChromiumに5Mbps・遅延80msを設定し、タイトル・人物と物の表示準備・背景を別々に測定。表示準備は操作のロックではありません。通信が止まっていても、先に表示できた物は操作できます。公開サイト自体の速度測定とは区別します。

メインJSの失敗と再読み込み、サブパスの公開フォルダ、全素材の存在とハッシュ、キャッシュ、BGMのバイナリ一致も確認します。

最終ビルドの起動検証では、タイトル842ms、最初の人物・物の表示準備1839ms、背景5405ms。背景は人物・物の準備と操作の完了条件に含めません。再読込時の対象リソース転送は505,839バイトから0バイトになりました。これらはローカルの5Mbps・遅延80msでの実測値で、公開サイトの速度を保証する値ではありません。

## 全体検証

`npm test` で全50Stage・272動作、53失敗とRetry、BAG、暗号、100件のPC表示、150件の奥行き比較、音声、通信を無効にした単体版の部屋移動を検証。全体の画面点検は背景の描画完了も待って撮影します。

すべて通過。最終の読み込み条件へ調整後、起動・障害回復テストと全50Stage・272動作を再実行し、最終公開JSでも通過しました。50Stageすべてでゲーム機の同一実体を維持し、ブラウザエラーは0件でした。

数値と対象HTML・JSのSHA-256は `VALIDATION_0.14.2.json`、実行結果はGit管理外の `test-results/v0142/`。本環境は `file:` の直接参照を禁止するため、単体版はローカルHTTPで読み込んでから通信を無効にして確認します。
