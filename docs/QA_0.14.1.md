# Ver0.14.1 起動時間の修正

## 原因と変更

Ver0.14.0の公開HTMLは84,698,018 bytesで、全画像・全音声をBase64で埋め込んでいました。JavaScriptがHTML末尾にあるため、ファイルが読み終わるまでタイトルの操作を始められませんでした。

- 公開HTMLを1,431 bytes、処理とデータを約367KB、CSSを約10KBへ分離。
- 素材は同じサイトの内容ハッシュ付きURLで配信。全50Stageの画像を起動時に転送しない。
- 元画像38点の転送用領域を可逆WebPへ符号化し、60,986,064 → 35,661,488 bytes。寸法・アルファと、アルファが0でない画素のRGBがすべて一致することを生成時に検証。元PNGは変更しない。
- 家具・小物は描画済みの領域だけ配信し、人物は同じキャラクターのポーズをまとめる。Web用カタログの原点だけを対応させ、見た目・当たり判定・手足のUVを保つ。
- 部屋の表示と動作に使う素材だけ準備し、読み込み数を表示。BGM・SEは操作開始後に取得し、起動や部屋の表示完了を待たせない。
- 通信失敗時は再試行できる。読み込み中もメニューへ戻れる。キャンセルしたStageの結果は新しい画面へ反映しない。
- 通常ビルドで公開用の `dist/web/` と、従来の単体オフライン版 `dist/offline/papa-hide-game.html` を別々に生成。GitHub Pagesは公開用フォルダだけを配信。

## 起動の実ブラウザ検証

Playwright / Chromiumで、ローカルHTTPサーバーに回線速度5Mbps・遅延80msを設定。実際の公開サイトの速度測定とは区別します。

- 変更前は4秒の測定枠内にタイトルの操作準備が終わらないことを確認。
- 変更後は画像の通信を意図的に保留してもタイトルと50件のStage Selectを操作できることを確認。
- 初回表示時に音声を取得しないこと、読み込み中のメニュー復帰、画像失敗時の再試行、メインJS失敗時の再読み込みを確認。
- 公開するフォルダをサブパスで配信して、相対URLとStage1の素材読み込みを検証。
- 再読み込みで同じ画像・JS・CSSがキャッシュから取得されることを確認。
- 公開BGMのバイナリのSHA-256が元音源と一致することを確認。

数値は `VALIDATION_0.14.1.json` とGit管理外の `test-results/v0141/startup.json`。起動測定はタイトルの操作準備までで、各部屋の全画像の転送完了時間とは異なります。

## ゲームの回帰検証

`npm test` は起動の検証に加え、全50Stage・272動作、53失敗ルートとRetry、BAG、暗号、150件の奥行き比較、100件のPC表示、音声を検証します。単体版はローカルHTTPで開いたあと接続を無効にし、部屋をまたぐ操作を検証します。この環境の管理ブラウザは `file:` の直接参照を禁止しているため、ファイルのダブルクリック起動の確認は含みません。描画と操作の基準は `QA_0.14.md` も参照してください。

最終版の初回Stage1の素材準備までの時間も、5Mbps・遅延80msで別途計測しています。タイトルのみの時間と区別し、`first-room-speed.json` と検証記録へ保存しています。

実行結果: 全50Stage・272動作、53失敗とRetry、入力ガード・音声、100件のPC表示、150件の奥行き比較を通過。最後に起動テストを追加実行し、5Mbpsでタイトル 923ms、初回Stage1の準備完了 9401ms、公開素材 215件のファイルとハッシュ一致を確認しました。
