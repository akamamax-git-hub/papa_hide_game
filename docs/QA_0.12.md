# Ver0.12 検証と評価

## 今回の問題と変更

1. 人物と部屋の縮尺: 1200×800の共通座標に統一。人物の透明余白を除いた描画範囲を採寸し、成人・子ども・家具に基準寸法を設定。奥行に応じて人物の寸法を変え、背景の縦横比を維持。
2. アイテム不在: 全50Stageの物と取得元を宣言。棚や引き出し内の物は実際の親オブジェクトを持ち、取り出してからBAGへ入る。受け渡し・設置・電池の組込み・本の配置は所持状態と描画を同時更新。
3. 選択肢と動作の不一致: 各手順に操作対象・担当人物・動作種別を明示。接近・予備動作・操作・回復を実描画で行い、処理完了後に次の手順へ進む。最終手順ではゲーム機が収納から現れ少年の手へ移る。
4. 不足したストーリー: アヒル、ドライヤー、お茶、虫取り網、猫のおやつ、最終Stageのコーヒー準備等の入手手順を補完。猫を追うStage49は玄関→庭→子ども部屋→リビングの順で遷移。
5. 不足した絵: 新しい空の部屋を背景に使い、必要な家具・人物・小物だけを配置。旧小物の白い背景や文字片を持ち込まない。窓の二重描画を除去。開閉・水・光・秤量結果を表示。

## 検証方法

- `python3 scripts/audit_storyboards.py`: 全50Stageの参照、素材、人物、取得元、前提道具を監査。
- `node tests/story-world.cjs`: 全Stageを実ブラウザの物・人物クリックで通す。クリックを強制せず、描画されていて実際にクリックできる箇所を選ぶ。対象が完全に隠れている場合は失敗。
- 各動作の実DOM座標とスプライトを `requestAnimationFrame` ごとに記録。移動とポーズ差分の両方がなければ失敗。テスト専用の進行バイパスは使わない。
- 取得後の部屋/BAGの状態、受け渡し先、開いた状態、全ノードの画面境界を毎手順で検証。
- 正解ルートに加え、53件の失敗条件とリトライを検証。別室の対象を操作する失敗選択肢は、その部屋へ到達するまで表示しない。
- `node tests/interaction-guards.cjs`: 誤った道具選択、BAGの実ドラッグ、再利用道具の保持、連打、アニメーション中のRetry/Menu、パズル中断と誤入力、ロード後オフラインの部屋移動、2種類のPC画面サイズ×50Stage、音声デコード・切替。
- 実画面キャプチャとStage別ログ: `test-results/v012/`（Git管理外）。集計は `VALIDATION_0.12.json` と `STAGE_AUDIT_0.12.csv` に保存。

実行結果は機械判定です。静止画一覧と代表的な中間画面の目視確認も行いますが、人間が自由に遊んだ場合のあらゆる操作順や面白さを保証するものではありません。

## 音源の検証

BGMは提供されたM4AとSHA-256が一致し、置換・再圧縮していません。AAC 128kbps、44.1kHz、ステレオ、約135.82秒。
測定値は約-12.8 LUFS、LRA 6.1 LU、デコード後ピーク約+1.69 dBFS（真のピーク約+1.7 dBTP）。ゲームの音量0.28を反映したピーク推定は約-9.37 dBFS、ラウドネス推定は約-23.86 LUFSです。元のピーク超過から、聴感上の歪みを断定することはできません。
先頭100msのRMSは約-16.0 dBFS、末尾100msは約-100.4 dBFS。現在はファイル全体を繰り返しており、音楽的に自然なループ点を検証・設定した状態ではありません。
実スピーカーでの聴感評価はしていません。曲の好み、音楽としての自然さ、声とBGMの聴感バランスは未確認です。場面別のBGM、フェード、効果音時のダッキングも未実装です。

## 遊びとしての評価

操作・結果の対応は旧版から改善しますが、基本は順序に沿った探索です。正解行動が文章で提示され、失敗行動も明示されるため、自分で発見する余地と難易度には限界があります。キャラクターは制作済みのキーポーズを切り替える方式で、すべての動作が滑らかな専用フルアニメーションになったわけではありません。

## 更新時

ストーリーを編集したら `python3 scripts/storyboard.py`、素材の表示範囲を再採寸する場合だけ Pillow を入れて `python3 scripts/catalog.py`。その後 `npm run build`。生成済みの単一HTMLを直接修正しないでください。
